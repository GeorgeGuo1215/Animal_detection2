# 设置与记忆管理增量规格

## 已确认行为

- 设置页保留聊天侧边栏；会员计划使用独立完整页面。
- 用户删除历史会话时写入 `status/deleted_at` 并从列表隐藏；会话、消息、Run、事件和专家意见在配置的清理期限内继续保留，不删除任何 Memory 数据，也不触发记忆重建。
- 记忆不存在“隐藏”：保留即参与正常生命周期，删除即物理删除。
- 记忆管理分为“近期记忆、长期记忆、用户画像”三个可见分区；支持近期记忆单条删除，长期知识和画像叶子字段精确删除，不开放中期段直接操作。
- 每个可见分区提供独立清空按钮并二次确认，不要求再次输入密码。清空近期记忆不会删除已经形成的长期记忆或画像；清空长期记忆/画像按来源关系清理不再支撑其他长期目标的独占中期段，共享中期段保留。
- 中长期记忆不保留 `turn -> memory` 来源关系，中期页不保存 `sourceTurnId`。
- 邀请码本期只提供登录用户兑换，不提供创建、查询或撤销管理接口。

## 中长期依赖规则

`memory_derivations` 只记录 `segment -> knowledge/profile` 的生成依赖和生成标签。

- 删除长期知识或画像字段：精确删除目标及其全部依赖边；依赖边移除后成为孤儿的独占中期段及页面级联删除，共享中期段保持不变。
- 中期页面分析完成后保持 `analyzed=true`，删除长期项不会因空闲任务自动从旧页面重新生成。
- 记忆管理不开放中期段的直接删除入口；中期段只会在独占长期目标被删除或系统容量汰换时清理。
- 系统容量汰换中期段时允许把段摘要沉淀为长期知识，这是生命周期迁移，不属于用户删除。

## 安全与并发

- 记忆列表、单条删除、分类清空和邀请码兑换使用用户、IP、路由联合限流；生产 Redis 不可用时敏感写请求失败关闭。
- 删除和记忆 worker 对同一用户使用 PostgreSQL advisory transaction lock 串行化。
- 邀请码兑换接受 `Idempotency-Key`，并通过邀请码行锁、唯一兑换约束和额度账本幂等键保证只发放一次；重复删除已不存在的记忆返回404，不重复影响其他层级。
- 邀请码只保存摘要和前缀；不存在、过期、撤销和次数耗尽返回相同错误。
- 单条删除与分类清空只要求登录态和前端确认弹窗，不传密码或确认文本；审计日志不保存记忆正文或完整邀请码。

## 备份恢复

- 管理员快照同时包含平台会话数据和 Memory Service 全部层级，但两者保持独立生命周期。
- 恢复采用版本、用户归属和 SHA-256 校验后的覆盖写入。
- 快照 schema v2 不包含中期页 `sourceTurnId` 或任何 `turn` 来源边。
