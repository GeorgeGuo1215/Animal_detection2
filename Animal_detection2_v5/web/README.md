# 毫米波雷达犬用心率/呼吸率 Web 系统

版本：2026-07-21 v5（低频伪峰防自锁版）

该目录可独立部署，是 `Animal_detection2` 的浏览器端实时采集、算法处理和可视化页面。v5 在 v4 采样时钟修复之上，继续修复“实际 70–90 bpm、算法长期显示 35–55 bpm”的低频伪峰选择与历史自锁问题，同时保留真实犬只低心率的检测通道。

## 本版生理参数算法

- 心率技术搜索范围：35–260 bpm，可在设置面板调整。
- 呼吸率技术搜索范围：6–60 次/分，可在设置面板调整。
- 设置面板的默认/备用采样率为 50 Hz；实时 BLE 同时核对浏览器单调到达时钟、设备时间戳和连接累计帧率。
- BLE 通知携带的帧数可以变化。系统按长时间跨度的“累计帧序号/单调时间”斜率估计，不再对每次通知的瞬时率取中位数。
- 采样率来源接近 2:1 冲突时，结合近期时间轴新鲜度阻断 80→40，同时避免陈旧连接平均把 80 翻成 160。
- BLE 已连接时，设置面板的 50 Hz 不能覆盖已验证的实时采样率；Tcycle 或实测采样率阶跃会开启新 sampling epoch，禁止新旧速率混窗。
- 离线文件使用独立处理器，不会覆盖实时 BLE 的采样时钟。
- 默认短窗：完整 20 秒后才开始，每 1 秒更新；30 秒长窗作为无历史提示的独立校验。
- 无有效信号时输出 `NaN`/`--`，不伪造 70、72 或 80 bpm。
- 心率与呼吸率分别跟踪；首次预热覆盖至少 2 秒新增数据，大幅变化确认覆盖至少 4 秒，不能把两个重叠 95% 的滑窗当作独立重复证据。
- HR 候选只由未经呼吸陷波的原始频谱产生，RR 抑制谱只负责重权，不能再把陷波两侧的 37/43 bpm 人造肩峰当成心率。
- 35–66 bpm 低候选会与全部较高候选及 RR 重叠关系联合复核，不再只检查严格 2 倍频。错误的 `fresh 40` 历史仅作软提示，不能否决后来出现的强 75–90 bpm 峰。
- 单窗 40/80 物理不可辨或 HR/RR 选到同一低峰时标记歧义并降低置信度，保持上一可靠值；首次低于 65 bpm 的候选等待长窗同意，但并不把低心率硬改成高心率。
- 短窗和长窗相差超过容差时，冲突会真正否决新基线；已有可靠值时只采用与基线独立一致的一侧。
- ACC/Gyro 按 0.5 秒分段建立自适应静止基线，短时运动只屏蔽局部相位段，不再作废完整 20/30 秒窗口。
- 运动时禁止可疑新峰覆盖基线；最近可靠值保持最多 30 秒并显示年龄。超过 30 秒后页面仍灰色保留历史数字，但内部状态为 `expired`，不能触发报警或进入新鲜值统计。
- HR/RR 独立标记 `fresh`、`held`、`expired`；例如 HR 可恢复实时更新而 RR 继续保持。
- 自动识别 ACC 的 `g` 与 `m/s²` 量纲；IMU 缺失或全零时回退为雷达自身质量控制，不把缺失数据误判成强运动。
- 支持 `freqBP`（相位频域带通）与 `cwt`（相位 CWT 滤波器组）两种提取器，二者共享同一套 I/Q 校正、质量控制和跟踪逻辑。

技术范围并不等于每只犬的正常生理范围，也不是临床诊断阈值。真实准确度必须用同步 ECG 和独立呼吸参考设备做分层验证。

## 算法流程

1. 严格解析 3 列、4 列或 BLE V1.02 16 字段数据，剔除控制帧、拼包和极端值。
2. 用单调到达时钟、设备时钟和累计帧计数交叉估计实际采样率，并在阶跃时切换 sampling epoch。
3. 对 I/Q 做异常点抑制、圆心校正；圆拟合不可用时回退 PCA，并做 `atan2` 相位差分解调。
4. 去趋势、异常点抑制后，按实际采样率构造心率/呼吸率频带。
5. 联合频谱峰显著度、自相关、有效周期数和信噪比评分。
6. RR 证据采用连续权重，没有 0.249/0.250 的硬开关；HR 对 35–66 bpm 低峰、非严格倍频高峰及 HR/RR 同频做多候选消歧。
7. ACC/Gyro 低通去重力、0.5 秒局部分段、自适应底噪门限，并对短运动段做相位插值修复。
8. 质量与置信度门控后独立跟踪 HR/RR；运动时保持最近可靠值并记录新鲜度，强运动候选不能更新基线。
9. 页面、录制、情绪模块和上传接口统一使用同一个最终结果；保持值不参与 HRV、会话平均值或报警。

## 快速开始

不要直接双击 `index.html`；请通过本地或部署后的 HTTP 服务访问：

```bash
cd web
python3 -m http.server 8000
```

浏览器打开 `http://127.0.0.1:8000/index.html`。Chrome/Edge 的 Web Bluetooth 通常要求 HTTPS 或 localhost 安全上下文。

连接设备后确认：

- 查看页面运行诊断中的 `fs、到达、设备钟、累计、帧/通知`，确认算法采用硬件的实际帧率。实际可为 50 或 100 Hz，不能只看设置框。
- 项圈稳定贴合，雷达视场覆盖胸壁。轻微移动时页面应显示黄色“运动保护/保持”；持续强运动时可显示灰色历史值与年龄，但不能把它理解成当前新测量。
- 设置中的采样率、心率范围和呼吸率范围与实验方案一致。

点击“模拟测试”可走通页面的完整 I/Q、解析、算法、跟踪和显示链路。内置模拟目标为 75 bpm / 18 次/分。

## 输入格式

支持以下每行格式：

```text
timestamp I Q
date time I Q
$MAC,Time,Lon,Lat,Ax,Ay,Az,Gx,Gy,Gz,Roll,Pitch,Yaw,V1,V2,V3*
```

V1.02 协议使用 `V2` 作为 I、`V3` 作为 Q。`$AT...` 响应不会进入生理信号缓冲区。

## 回归测试

需要 Node.js 18 或更高版本，无需安装 npm 依赖：

```bash
node --check app.js
node --check bluetooth.js
node --check cwt-vitals.js
node --check vitals-tracker.js
node --check radar-processor.js
node --test tests/*.test.cjs
```

当前自动回归为 **109/109 通过**。除 35–260 bpm、6–60 次/分、运动连续性和无效信号外，还专门覆盖 BLE `1/1/1/5` 可变打包、采样率 2:1 双向冲突、80+强40伪影、错误 fresh-40 提示恢复、HR80/RR40 重叠、短/长窗 40/80 冲突、完整20秒启动门槛及滑窗独立证据时长。

## 上线前必须完成

仓库内没有同步 ECG 标签，也没有独立呼吸真值，因此当前测试只能证明软件不再结构性锁在 80 bpm、可覆盖宽频合成信号，不能证明具体硬件已达到临床精度。请按[犬用心率呼吸算法升级说明](./CANINE_VITALS_ALGORITHM_ZH.md)完成 ECG/呼吸参考设备验证后，再确定量产参数和报警阈值。
