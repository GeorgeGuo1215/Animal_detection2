# 犬用毫米波雷达心率/呼吸率算法升级与验收说明

版本：2026-07-21 v5（低频伪峰防自锁与独立长窗校验）

## 1. 结论

本次修改解决五类确定性软件问题：旧链路锁在约 80 bpm、BLE 可变打包使采样时钟减半、40/80 bpm 低峰被历史提示永久自锁、RR 陷波制造 37/43 bpm 人造峰，以及轻微移动后 HR/RR 一起被清空。系统现在同时维护可验证的采样时钟、原始频谱候选、低/高双假设、独立长窗校验、局部运动修复和带新鲜度的连续显示状态机。干净及运动扰动的合成回归已覆盖主要软件路径，但仓库没有同步 ECG 或呼吸真值，因此不能仅凭这些测试宣称硬件已经具备临床级精度。

## 2. 原问题的直接原因

旧实时页面存在多条互相覆盖的心率计算/显示链路，其中旧链路对 30 秒、约 50 Hz 数据补零到 2048 点，却固定搜索 FFT 第 9–20 个 bin，最后又直接用 `bin × 6` 映射成 bpm。这个区间在实际频率上更接近呼吸频带，18–21 次/分的呼吸峰会被显示成约 72–84 bpm；同时该写法天然只能输出 54–120 bpm。

另外还有三个锁定来源：

- 心率历史数组预填了 200 个 `70`，呼吸历史预填了 200 个 `18`，但界面所称的平滑窗是 30，导致真实变化要很久才能改变平均值。
- 单次变化超过 25 bpm 会一直被拒绝，没有“持续变化确认”路径；因此 85→45 或 85→200 这样的真实变化也无法通过。
- 新算法结果只写入诊断字段，旧算法随后又覆盖页面、录制和上传使用的主字段。

本版删除了实时旧算法调用，不再预填默认值，并将页面、记录、情绪模块和上传的 HR/RR 统一到一个发布函数。

### 2.1 现场发现的“80多显示30–45”二次问题

真实实验进一步证明，v3 的“固定每通知两帧”修复仍不完整。BLE 每次通知解出的完整帧数可能是 `1、1、1、5`循环；通知频率 25 次/秒时，平均仍为 2 帧/通知，真实帧率是 50 Hz。旧方法得到瞬时候选 `25、25、25、125 Hz`，中位数却是 25 Hz。频谱换算满足：

```text
HR输出 = HR真实 × fs使用 / fs实际
```

所以真实 80 bpm 会精确变成约 40 bpm。v4 改为：

1. `bluetooth.js` 给同一次通知解出的帧附加相同 `notificationId` 和 `performance.now()` 单调到达时间。
2. 使用长时间跨度上的“累计帧序号/时间”斜率，不再对单通知瞬时率取中位数。
3. 同时核对设备钟、单调到达钟和连接帧计数。接近 2:1 冲突时，新鲜的多秒时间轴优先；旧/短时间轴则先阻断低值。
4. BLE 已连接时，设置面板的默认 50 Hz 不能覆盖已验证的实时采样率。
5. Tcycle 或实测采样率阶跃后建立新 sampling epoch，清除混合速率的 I/Q 窗口，但保留最近可靠显示并标记为 `held`。
6. 离线文件处理器与实时处理器隔离，打开 50 Hz 文件不会再覆盖实时 100 Hz。

Tcycle 写入成功只表示 GATT 指令已发送；页面仍等待实际帧流验证，目标率与算法采用率分开显示。

### 2.2 40/80 bpm 八度歧义与旧提示自锁

v3/v4 的 HR 倍频判断还存在四条锁低路径：把用户设置的 RR 上限间接带入 HR 排序；用过窄区间只检查约 49 bpm 以下的严格二倍频；上峰略低于固定阈值时把低峰当成“非歧义高置信”；已被错选的 fresh 40 bpm 历史又会在评估强上峰前直接返回低值。v5 对 35–66 bpm 低候选复核全部较高峰，同时把历史改为软证据。即使旧显示为 fresh 40，只要当前 75–90 bpm 峰具有独立强证据，也必须恢复高峰；反之证据不足就标记歧义，历史不能替低峰增加置信度。

必须承认一个物理局限：单个频谱同时出现 40 和 80 两条谱线时，“真实 40 + 80 二次谐波”与“真实 80 + 40 次谐波/运动伪影”可能在数学上不可辨。此时算法明确标记 `ambiguous`、将置信度降到不能建立新基线，而不是盲目乘二或继续锁在 40。

### 2.3 RR 陷波肩峰、同频复用与长窗失效

v4 先按 RR 在 HR 频谱上打深陷波，再把原始谱和陷波谱的局部峰合并。陷波两侧会自然出现新的局部最大值；在“真实 HR=80、RR=40”的确定性信号中，旧算法可把并不存在的 37/43 bpm 肩峰以高置信发布。v5 做了四项约束：

1. HR 候选只能从未经修改的原始频谱产生；RR 抑制谱只能给已有原始峰重权，不能新增峰。
2. RR 证据从硬阈值改为连续权重，避免置信度 0.249 与 0.250 产生完全不同的 HR 排序。
3. HR 与 RR 选择同一低频，或低 HR 明确贴近 RR 整数谐波时，设置跨频带歧义；只有存在可信且更不像呼吸的高峰时才切换。
4. 短窗与30秒长窗冲突时不再“只记录日志仍采用短窗”。无基线时拒绝两者；有基线时只采用与已有可靠轨迹一致的一侧。长窗运行时不带 HR 历史提示，避免把同一个错误复制两遍。

首次分析还必须等满配置的20秒，不再12秒提前运行。预热除窗口数外还要求至少2秒新增数据，大跳变确认要求至少4秒；低于65 bpm的首次候选等待长窗同意，但低心率搜索下限仍保留35 bpm，所以这不是把所有低值强制乘二。

### 2.4 轻微移动后数字消失的原因与修复

旧运动门控对完整20秒或30秒窗口计算三轴方差RMS，并把同一个质量分数同时施加给HR和RR。运动RMS接近0.17 g时整个窗口直接无效，随后跟踪器连续5个1秒周期无效便清空两个数字。即使项圈已经停止，旧运动段仍留在长窗口内，因此恢复可能需要20–30秒。

v3 引入、v5 保留并增强以下策略：

1. 根据重力模长自动识别ACC是`g`还是`m/s²`。
2. 用0.8秒时间常数低通跟踪重力方向，项圈姿态阶跃不会污染整个窗口。
3. 每0.5秒计算一段抗异常点动态加速度/陀螺仪能量，静止底噪采用窗口低分位数与MAD自适应估计。
4. 短运动段连同前0.25秒、后0.50秒保护区只在局部标记；在均匀时间轴上对相位做插值，不把不连续片段直接拼接后FFT。
5. 近期持续强运动时不接受任何新候选，避免把步态或晃动频率当成HR/RR。
6. HR和RR分别维护最后可靠时间、状态和保持年龄；停止运动后，接近原基线的第一个高置信窗口即可恢复`fresh`。

如果强运动持续超过30秒，内部当前值会过期，报警与统计不得使用；页面仍灰色显示最后可靠数字和距今时间。这种设计既保证操作者不会突然失去全部信息，也不会把旧数字冒充成持续精准的新测量。

## 3. 新算法结构

```text
BLE/文件
  → 严格分帧与字段校验
  → 单调到达钟/设备钟/累计帧率交叉验证
  → sampling epoch 隔离变采样率窗口
  → ACC/Gyro量纲检查、低通去重力与0.5秒运动分段
  → I/Q 异常点抑制、圆心校正/PCA回退
  → atan2 差分相位展开
  → 去趋势/异常值抑制/局部运动段插值修复
  → RR 与 HR 自适应频带
  → 频谱峰 + 自相关 + SNR + 周期数评分
  → 原始HR候选 + 连续RR证据 + 跨频带歧义检查
  → 低/高HR多假设与独立长窗校验
  → HR/RR独立的干净时长、置信度与运动质量门控
  → fresh/held/expired 独立状态跟踪
  → 页面/记录/上传统一发布
```

两个方法的差别只在频带提取：

- `freqBP`：在频域使用平滑边缘带通。
- `cwt`：使用对数频率高斯小波滤波器组重构目标频带。

两者都只使用一次 Hann 窗，避免旧代码重复加窗造成边缘峰偏差。呼吸谐波处理采用候选峰惩罚；当真实心率恰好接近呼吸的整数倍时，不会把整个区域硬删除。

## 4. 默认参数

| 参数 | 默认值 | 说明 |
|---|---:|---|
| 采样率备用值 | 50 Hz | BLE 实时处理以三源交叉验证的实际帧率为准 |
| HR 搜索范围 | 35–260 bpm | 技术范围，不是正常值范围 |
| RR 搜索范围 | 6–60 次/分 | 技术范围，不是报警阈值 |
| 短窗 | 完整20秒 | 数据未满不提前运行；之后每1秒滑动更新 |
| 长窗校验 | 30 秒 | 无HR历史提示的独立判断 |
| 预热最小证据跨度 | 2 秒 | 兼顾首次输出速度与滑窗独立性 |
| 大跳变最小证据跨度 | 4 秒 | 防止高度重叠滑窗冒充独立重复测量 |
| 首次低HR长窗门槛 | <65 bpm | 等待长窗同意；不改变35 bpm技术下限 |
| IMU运动分段 | 0.5 秒 | 局部判断，不再用整窗单一RMS |
| 重力跟踪时间常数 | 0.8 秒 | 项圈转动后快速适应重力方向 |
| HR最少干净数据 | 8 秒且40% | 不足时HR保持上次可靠值 |
| RR最少干净数据 | 14 秒且60% | RR比HR需要更长周期，独立保持 |
| 可靠值内部保持 | 30 秒 | 期间状态为held，新峰不得由强运动更新 |
| 超过保持时间 | 页面继续灰色显示 | 状态为expired，只是历史值，不参与报警/平均值 |
| 有效中位窗 | 3 | 不预填任何默认值 |
| 大幅 HR 变化阈值 | 25 bpm | 连续 3 个高置信窗后接受 |
| 大幅 RR 变化阈值 | 8 次/分 | HR/RR 分开确认 |

代码按配置的最高心率检查 Nyquist 裕量。以 260 bpm 为例，内部要求 `fs ≥ 4.333 / 0.45 ≈ 9.63 Hz`；低于该值直接输出无效。工程上仍建议固定 50 Hz，因为低采样率的时间量化、丢帧和谐波混叠会显著降低真实犬只数据的鲁棒性。仓库中的约 2 Hz 上报样例在物理上不能测量大于约 60 bpm 的心率。

## 5. 输出语义

- `HR_bpm`、`RR_bpm`：通过质量门控和跟踪后的当前值；`held`期间是时间受限的最近可靠值，`expired`后内部为无效。
- `raw_HR_bpm`、`raw_RR_bpm`：当前短窗原始候选，仅用于诊断。
- `HR_confidence`、`RR_confidence`：0–1 的算法相对置信度，不是误差概率。
- `quality.score`：I/Q 几何、相位、异常点和运动质量的综合分数。
- `continuity.status.HR/RR`：`warming`、`fresh`、`held` 或 `expired`。
- `continuity.ageMs.HR/RR`：距离该指标最后一次新鲜可靠测量的时间。
- 页面颜色：蓝绿色为实时值，黄色为运动/低质量保持，灰色为历史值且当前不可测。
- 从未得到过可靠值时才显示 `--`；得到过可靠值后即使持续运动，页面仍保留数字和年龄，但保持/历史值不会进入HRV、报警或新鲜值平均。

“连续显示”不等于“连续产生新测量”。运动时可以展示最后可靠值，但必须通过状态和年龄明确告知它不是当前新测量；量产报警链路仍坚持宁可无效、不报假值。

## 6. 文件变更

- `cwt-vitals.js`：原始谱HR候选、连续RR证据、35–66 bpm 多候选复核、fresh低值防自锁及局部运动修复。
- `vitals-tracker.js`：短/长窗冲突否决、独立证据时长、低HR首次长窗确认、`fresh/held/expired` 与30秒保持。
- `app.js`：完整20秒启动、无提示独立长窗、三源采样时钟、sampling epoch、统一发布和可复制候选峰诊断。
- `radar-processor.js`：严格文件解析、离线采样率估计，并复用同一提取器。
- `bluetooth.js`：UTF-8 流式解码，传递通知 ID/单调到达时间/帧索引，断线清空半帧。
- `index.html`：加载新跟踪器，更新范围和参数说明。
- `tests/`：合成 I/Q、采样率、状态跃迁、运动连续性、无效信号和解析回归测试。

## 7. 当前自动化验收结果

运行：

```bash
cd web
node --test tests/*.test.cjs
```

当前自动回归结果为 **109/109 通过**。两个提取器均覆盖 35、45、75、90、120、180、220、260 bpm 以及 6–60 次/分；每个 HR 误差阈值为 5 bpm，每个 RR 误差阈值为 3 次/分。除采样时钟、运动和宽频范围外，v5 新增：弱80+强40只能输出正确值或低置信歧义、强80必须摆脱错误 fresh-40、HR80/RR40 不得发布37/43陷波肩峰、短40/长80冲突不得建立或替换80基线、完整20秒启动门槛，以及2秒预热/4秒跳变证据跨度。常量数据和不足128点的数据必须返回无效，禁止回退为70/72/80。

仓库既有记录按时间戳实际采样率做39个非重叠20秒窗重放：v4 有16个窗低于55 bpm，其中11个置信度达到页面发布门槛；v5 仍保留12个低候选用于诊断，但全部标记歧义，最高置信度0.152，达到发布门槛的低值为0。对较高窗口强制加入错误 fresh-40 提示时，v4 有16个重新锁低，v5 为0。`09-45` 记录按网页1秒步进重放并采用2秒预热证据后，约第23秒首次发布约78 bpm，整段没有发布低于55 bpm 的结果。由于这些旧记录没有同步ECG，该统计只能证明“歧义低峰不再被高置信发布”，不能证明较高候选就是真值。

网页“模拟测试”以 50 Hz 输入 75 bpm / 18 次/分，并在第18–19秒加入确定性的1秒强运动。现场验收时应观察到“实时可靠测量 → 运动保护（数值仍保留）→ 局部运动已剔除/恢复实时测量”的状态变化。该流程只验证软件链路，不是动物实验准确度结论。

## 8. ECG 与呼吸真值验收方案

### 8.1 设备与同步

1. ECG/Holter 作为心率真值；ECG 采样率建议至少 250 Hz，并保存原始 R 波时间戳。
2. 呼吸率不能只用 ECG 直接替代真值。同步使用呼吸感应带、阻抗呼吸、气流/二氧化碳设备，或由专业人员审核的胸廓视频/波形。
3. 雷达原始 I/Q、设备单调时间戳、ACC/Gyro、ECG 和呼吸参考必须保存，不只保存最终 bpm。
4. 开始/结束各做一次可识别的同步事件，估计固定时延和时钟漂移；每个 20 秒窗按重叠的 ECG R–R 间期重新计算真值。

### 8.2 分层采集

- 覆盖不同体型、胸围、毛长、品种、年龄和性别。
- 分开记录站、坐、趴、侧卧、睡眠、轻微运动、剧烈运动和喘气。
- 心率分层至少包含 `<70`、`70–100`、`100–160`、`160–220`、`>220 bpm`；仅记录自然或兽医监督下出现的区间，不人为诱发危险心率。
- 每只犬每个静息姿态至少 5–10 分钟，并按犬只划分训练/验证/测试，不能把同一只犬的相邻窗随机分到两侧。

### 8.3 每窗统计

- HR：MAE、RMSE、偏差、95% 一致性界限、绝对误差 ≤5/10 bpm 比例、有效覆盖率。
- RR：同样指标，另报告喘气状态覆盖率。
- 按心率层、姿态、犬只、运动质量、信号质量分别报告；总体平均值不能掩盖低/高心率失效。
- 单独评估 85→45、85→200 等变化的检测延迟、过冲和误报。

建议的工程验收目标需由产品/兽医团队最终确认。一个可操作的起点是：静息状态 HR MAE ≤5 bpm、95% 绝对误差 ≤10 bpm、有效覆盖率 ≥90%；RR MAE ≤3 次/分。未达标时应保留无效输出并调整贴合、天线/射频、采样时序或分层模型，而不是放宽置信度门限来填数。

## 9. 仍需硬件/数据团队确认

- 固件 Tcycle 目标与实际输出帧率的关系，时间戳单位、BLE 可变打包和补传行为是否明确。
- I/Q 是否饱和、直流漂移、天线方向和项圈松紧对犬只体型的影响。
- 网页会按重力模长自动识别 ACC 的 `g`/`m/s²`，但固件仍应明确协议量纲，并确认 ACC/Gyro 与 I/Q 时间对齐；运动质量阈值必须再用真实犬只数据标定。
- 低/高心率真实数据中主峰、呼吸谐波和步态谐波的分布。
- 每个失败窗都应保存原始数据与原因码，建立可复现的困难样本集。

只有完成以上同步真值验证后，才能对“硬件精准测量”作量化声明。
